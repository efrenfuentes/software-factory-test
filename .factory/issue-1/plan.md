# Plan — Issue #1: Initialize an Axum API

## Approach
Create one Cargo binary crate at the repository root. Split it into a small library part
(`src/lib.rs`, which exposes `app() -> axum::Router`) and a thin binary (`src/main.rs`, which
binds a `tokio::net::TcpListener` and calls `axum::serve`). Integration tests in `tests/` can
then drive the router in-process with `tower::ServiceExt::oneshot`, so no real port is needed.

The handler returns `axum::Json` holding a small `#[derive(Serialize)]` struct
(`HealthResponse { status: &'static str }`). That produces `Content-Type: application/json`
and a stable body. `serde_json::json!` would also work, but a typed struct documents the contract better.

## Files to create or change
| File | Why |

| `Cargo.toml` | Package `software-factory-test`, edition 2024, `rust-version = "1.99"`. Deps: `axum`, `tokio` (features `macros`, `rt-multi-thread`, `net`), `serde` (feature `derive`). Dev-deps: `tower` (feature `util`, for `oneshot`), `http-body-util` (to collect the body), `serde_json` (to parse the body in tests). |

| `src/main.rs` | `#[tokio::main]`: read `PORT` (default `3000`), bind `0.0.0.0:{port}`, print the address, then `axum::serve(listener, app()).await`. |
| `tests/health.rs` | Integration tests (see Testing). |
| `README.md` | Prerequisites (mise / Rust 1.99.1), `cargo run`, `cargo test`, sample `curl http://localhost:3000/health`. |

`mise.toml` already pins Rust and is not changed.

## API changes
New endpoint:
- `GET /health` → `200 OK`, `Content-Type: application/json`, body `{"status":"ok"}`.

There is no data or schema work.

## Risks
- **Axum version API drift**: Axum 0.7 and later use `axum::serve` + `tokio::net::TcpListener`; older examples (`axum::Server`) won't compile. Use `cargo add axum tokio ...` to get the latest versions and follow their docs. In Axum 0.8 and later, path parameter syntax changed to `{param}`, but that doesn't matter for `/health`.
- **Toolchain availability**: the sandbox must have Rust 1.99.1 (via `mise install`). If it doesn't, any recent stable toolchain that supports edition 2024 works.
- **Dev-dependency versions**: `tower` and `http-body-util` must match the versions Axum uses (`tower` 0.5, `http-body-util` 0.1) so that trait impls line up. `cargo add` with no version pin picks compatible ones.

## Testing
`tests/health.rs` with `#[tokio::test]`:
1. `health_returns_ok_json`: `app().oneshot(Request::get("/health").body(Body::empty()))`. Assert status `200`, assert the `content-type` header is `application/json`, collect the body with `http_body_util::BodyExt::collect`, parse it with `serde_json`, and assert it equals `json!({"status":"ok"})`.
2. `unknown_route_returns_404`: `GET /does-not-exist` → `404`.

Quality gates: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
Manual smoke test: `cargo run`, then `curl -i http://localhost:3000/health`.
